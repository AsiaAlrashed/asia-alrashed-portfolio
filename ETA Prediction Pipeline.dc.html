Delivery ETA Prediction

A supervised model that estimates when a shipment will actually arrive, learned from what past shipments did rather than from a fixed transit-time table.

Data foundation This model trains on the reconciled dataset produced by a separate data engineering project. Multi-Year Logistics Data Migration →
( A ) The problem

A promised date that ignores how shipments really behave

Customers want to know when a shipment will arrive, and operations needs the same answer to plan. A static transit estimate per route gives one number regardless of what is actually happening, so it is confidently wrong for exactly the shipments that need attention.

The historical data contained the answer: thousands of past shipments and how long each one really took. That makes it a supervised regression problem, where the useful work is choosing which features carry signal about delay.

( B ) The workflow

Prepare, engineer, train, evaluate, predict

Historical shipment records ↓ Data preparation and validation ↓ Feature engineering ↓ Model training ↓ Evaluation and tuning ↓ Predicted arrival time
Feature engineering

The core of the work. Signal about delivery time lives in the shape of the shipment and its context, so features were derived from the historical record rather than fed in raw.

Training

Trained with Scikit-learn on the prepared dataset, with the target being the observed delivery duration of each completed shipment.

Evaluation

Assessed on held-out shipments and compared against the naive baseline of a fixed per-route estimate, which is the bar it has to clear to be worth using.

( C ) Modeling decisions

Why it was built this way

Regression, not classification

Operations needs a duration, not a late or on-time flag. Predicting the value keeps the decision about what counts as late with the business.

Baseline first

The fixed per-route estimate was measured before any model was trained. Without that comparison there is no way to tell whether the model earns its complexity.

Only completed shipments

Training used shipments with a known outcome. In-flight records have no label, and including them would leak an assumption into the target.

Interpretable models first

Started with models whose behavior can be explained to operations. A prediction people cannot reason about does not get used, however good the error metric.

( D ) Impact

What it enables

Proactive communication. An expected arrival time can be shared before a customer has to ask.

Better planning. Operations can sequence work against predicted durations rather than a flat assumption.

Predictive workflows became possible. A trained model is the prerequisite for anything that acts on a forecast.

Scope of this write-up

No error metric is published for this model, so none is claimed here. The data engineering behind the training set is a separate case study and is not repeated on this page.
